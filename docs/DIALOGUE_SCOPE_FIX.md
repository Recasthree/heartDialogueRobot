# 症状与用药混合提问、多轮目标及用户措辞修复

日期：2026-09-30。范围为对话工程，不重洗数据、不修改来源审核字段。

## 复现与原因

- 00:38 的原 trace `1c4c023b-523b-4c37-b7b9-8236b5f50f09` 最终为 `unsafe_output`，安全模型调用为 0。旧代码将整个问题路由到用药分支，拒答会替换全部正文，因此一般症状问题也消失了。原始生成正文未保留，不能倒推该次究竟哪一句命中了规则。可以独立复现的是：旧输出规则会把“请不要自行停药”等否定句误判为停药指令。
- 下一轮原 trace `84a5979e-268b-49cb-aa0a-0c4f9388a3cd` 仍回答上一轮用药目标。历史任务与当前问题没有隔离，生成器还直接接收 `pending` 等内部字段。
- 用户写的是“心率不齐”；术语表与公共医学机构患者教育来源原来只匹配“心律不齐”，漏掉了可用的基础症状页面。修复仅作检索别名，不将其当作患者诊断。

## 实现

1. 保留原始消息急救优先。对包含独立症状/检查等目标的混合提问，先划定可回答范围，再按该范围分类、检索、生成；服务端追加单独的选药边界。纯处方/剂量请求仍拒绝，不凭空创造可回答问题。
2. 已有明确主题的独立问题不继承历史任务，不做多余改写；“它要做哪些检查”等指代式追问仍读取历史。病例事实和已确认画像不因此删除。
3. 否定用药建议不再被当作肯定指令；仍经过模型安全复核，剂量输出、真正停药/加量指令及复核失败保持阻断。
4. 生成器使用自然语言来源说明，不直接传审核枚举。用户正文的内部术语有兜底转写；实际不确定性不能隐去。引用和研究台仍保留原始审计字段，不将未审核资料改成已核验。
5. 给 `cited/mixed` 明确语义：有来源介绍加用药限制仍为 `cited`；网络与本地来源并用也不是“无来源模型补充”。校验失败记录服务器定义的具体错误码，最多一次带原因的修复，仍失败则明确告知引用校验失败，而非谎报资料不足。
6. 无伪造引用豁免。既有单来源格式修复只适用于模型已明确声明唯一合法 ID、仅漏正文编号的情形；之后仍进行安全复核。

## 使用及复现

正常访问 `http://127.0.0.1:8000/`，刷新并新建对话；网络补证保持开启。历史已生成消息不自动重算，也不删除用户的对话记录。

```powershell

.\scripts\run_python.ps1 -m pytest -q
.\scripts\run_python.ps1 -m scripts.verify_chat_ui

# 仅在重新授权付费预算后运行；此命令会调用真实模型
.\scripts\run_python.ps1 -m scripts.verify_dialogue_scope --live --case mixed --max-model-requests 6
```

这些测试验证请求范围、引用与安全流程，不构成临床有效性证明。真正网络失败、资料未覆盖或模型复核失败时仍应如实降级，不能保证任意医学问题都给出答案。

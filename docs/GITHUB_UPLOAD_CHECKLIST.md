# GitHub 上传清单

这份清单针对当前项目目录生成，目标是把可复现的代码和文档公开，同时排除密钥、个人环境、患者资料、第三方原始数据和运行产物。

## 建议上传

以下内容属于项目源代码、配置模板、测试或说明文档，可以作为首个公开版本的主体：

- `app/`：应用、Agent、检索、隐私、安全和工具代码
- `web/`：浏览器界面
- `config/mcp_servers.example.json`：配置示例；不要上传同目录的本地配置
- `prompts/`、`skills/`：提示词与安全规则
- `scripts/`：数据构建、索引、验证和启动脚本
- `tests/`：测试代码与脱敏测试夹具
- `docs/`：工程说明、验收记录和本清单
- `Dockerfile`、`docker-compose.yml`、`pyproject.toml`
- `requirements-*.txt`
- `.env.example`、`.env.local.example`：仅当其中没有真实密钥、Cookie、内网地址或个人路径
- `README.md`、`README_GITHUB.md`
- `data/DATASET_CATALOG.md`、`data/dataset_catalog.json`：仅作为数据说明和统计，不代表原始数据已获再分发许可
- 项目大纲等不含隐私和第三方受限内容的设计文档

## 默认不要上传

以下内容已通过 `.gitignore` 排除，不能用 `git add -f` 强行加入：

- `.env.local`、`.env.*.local`、真实 API Key、访问令牌、Cookie 和私钥
- `config/mcp_servers.local.json`
- `.venv-*`、`.runtime-deps/`、`__pycache__/`、`.pytest_cache/`、`*.egg-info/`
- `data/raw/`：下载的原始数据、压缩包、未完成下载和第三方数据集
- `data/processed/`：中间结果、缓存、翻译进度和大体积派生数据
- `data/verified/`：医学语料、评测案例、隐私/安全样本和可能受许可限制的派生数据
- `data/runtime/`：日志、进程号、SQLite、索引、截图、浏览器轨迹和测试运行记录
- SQLite、Chroma、Redis 数据、日志、缓存、`.part`/`.partial` 文件和虚拟环境

## 上传前必须人工确认

1. **数据授权**：第三方指南、论文、药品标签、数据集和转换结果是否允许公开再分发。仅有下载地址不等于可以把文件提交到 GitHub。
2. **隐私**：搜索患者姓名、手机号、身份证号、病历号、邮箱、地址、附件内容和真实对话；即使文件名看起来像测试数据，也要确认是否为合成数据。
3. **密钥历史**：不仅检查当前文件，也检查 Git 历史、终端输出、日志和截图。密钥一旦曾经提交过，应立即撤销并重新生成。
4. **许可证**：当前项目根目录没有许可证。公开前需要选择软件许可证，并单独记录第三方数据的许可证。
5. **可复现性**：确认 README 中的命令不依赖个人绝对路径、个人账号、付费 API 或本机已有数据库。

## 推荐的首个提交范围

```text
源代码 + 前端 + 测试 + 脱敏配置示例 + 工程文档 + 数据集说明
```

不建议首个提交包含任何医学原始语料或运行时索引。若未来确实需要公开数据，应单独建立数据发布说明，逐项写明来源、许可证、版本、哈希、脱敏方法和再分发限制。

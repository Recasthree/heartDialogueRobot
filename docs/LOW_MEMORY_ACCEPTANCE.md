## 资源及性能实测

- 全量关键词构建阶段记录的进程树峰值：752,721,920 字节，约 **0.70 GiB**。
- 当前任务记录的累计峰值：971,710,464 字节，约 **0.905 GiB**，包括旧缓存抽样验证的编码子进程。**不是整个向量阶段的最终峰值**；后续新内容编码会继续更新记录。
- 45,220 个唯一向量 BLOB 共 69,457,920 字节；不是把长 JSON 向量重复嵌入每条文档。
- 一次隔离验收中，索引句柄加载 **0.188 秒**，该进程随后 RSS **104,693,760 字节（约 100 MiB）**，编码器未加载。
- 同次完整应用启动 **32.388 秒**。索引句柄加载时间不等于完整应用启动时间；本轮后台写盘期间的重启更慢，不承诺固定启动延迟。
- 热缓存关键词诊断查询约 **0.5 秒**；实际 MCP 本地检索约 **1.2–1.7 秒**；另一次浏览器验收前的首条冷查询约 **7.88 秒**。这些是本机采样，不是 P95/P99 性能承诺。
- 报告采样时系统可用内存约 4.42 GiB；资源门限按批次检查，不修改系统分页文件。

这次未找到能确认用户先前退出由 OOM 引起的证据。实际修复了两个另外复现的问题：FTS 查询计划从元数据侧反复扫描导致慢查询，以及 Windows 读取进度文件期间原子替换发生共享冲突。前者改为有序 FTS 驱动查询，后者加入有限重试；已有检查点可继续使用。
